# DTOs and the API Contract

## Goal

Keep the API contract separate from the persistence model: one DTO per use case,
mapped from and to the entity in a single place, with a reusable query projection.

## Prerequisites

- C# records and extension methods
- LINQ and `IQueryable`
- .NET 10 SDK

## Task

`Game` is the persistence entity: it has a `GenreId`, a `Genre` navigation, and an `Id`
generated by the database. The API exposes four different shapes of it (`CreateGameDto`,
`UpdateGameDto`, `GameDetailsDto`, `GameSummaryDto`). All the mapping lives in
`GameMappingExtensions`, which currently throws. Implement it so handlers can read as
intent, for example `db.Games.Add(dto.ToEntity())`.

## Instructions

Complete the following TODOs:

- TODO-00: `ToEntity` from `CreateGameDto`, leaving `Id` unset.
- TODO-01: `ApplyTo` copies an `UpdateGameDto` onto an existing `Game` except `Id`.
