# EF Core Compiled Models and Startup Time

## Goal

Use a compiled model generated by `dotnet ef dbcontext optimize`, prove that EF Core stops
running `OnModelCreating`, measure the two startup phases, and write a check that notices
when the generated model is out of date. Everything runs against SQLite, so no database
server is needed.

## Prerequisites

- EF Core basics (`DbContext`, `OnModelCreating`)
- .NET 11 SDK (the lab targets `net11.0` and EF Core 11.0.0)

## Task

`LabContext` maps 60 small entities. The compiled model for it is already generated in
`src/CompiledModelLab/CompiledModels`. You write the code that uses it.

## Instructions

Complete the following TODOs in `LabDb.cs`:

- TODO-01: `Create` opens the context, with the compiled model when `compiled` is true.
- TODO-02: `MeasureStartup` times `db.Model` and the first query separately.
- TODO-03: `Shape` and `IsStale` compare a compiled model with the model EF Core would build now.

Run the tests until they all pass. The probe test prints the timings, run it with
`dotnet test --logger "console;verbosity=detailed"` to see them. The tests do not assert on
the numbers, because they change from machine to machine.

## Regenerating the model

The generated files are committed, but you can rebuild them (the tool version must match
the EF Core version, 11.0.0):

```bash
dotnet tool install --global dotnet-ef --version 11.0.0
cd src/CompiledModelLab
dotnet ef dbcontext optimize --output-dir CompiledModels --namespace CompiledModelLab.CompiledModels
```

`optimize` also writes `LabContextAssemblyAttributes.cs`. This lab deleted that file on
purpose: with the `[DbContextModel]` assembly attribute present, EF Core uses the compiled
model by itself, even without `UseModel`, and the "without a compiled model" case could not
be measured. Keep that in mind in a real project.

## Running the Lab

dotnet test
